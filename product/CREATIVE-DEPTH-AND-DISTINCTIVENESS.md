# Creative Depth & Distinctiveness Gate

## Purpose

COLLIDER must not stop at the first version that is functional, judgeable, safe, or easy to explain.

Two separate checks are mandatory:

1. **Creative Depth & Product Ambition** — before final Concept Lock, ask whether the product has been pushed beyond its first obvious formulation.
2. **Distinctiveness Escalation** — after Functional Proof and before Demo/Submission Lock, ask whether the working product still stops too early.

Execution constraints may sequence the vision; they must not define the vision.

---

## Canonical category

**COLLIDER — Semantic CI for Agentic Software Development**

> **Fuzz the specification. Repair the decision. Prove the system understands it.**

The narrow implementation is not the category. The deeper mechanism is:

`INTERPRETATION VARIATION → IMPLEMENTATION DIVERGENCE → MISSING DECISION`

Independent agents are treated as **ambiguity probes / specification fuzzers**, not merely parallel labor.

The product loop is:

`PROBE → COLLIDE → ADJUDICATE → DECIDE → COMPILE → PATCH → VERIFY → REMEMBER → GUARD`

A future `REPLAY` step remains part of the North Star, but is not claimed as executed until a genuinely fresh independent agent run is proven.

## Gate A — Creative Depth & Product Ambition

### Question

Is this the strongest product concept we can defend, or merely the first useful tool we found?

### Escalations tested

| Candidate escalation | Decision | Reason |
|---|---|---|
| Generic disagreement detector | REJECT | Too passive; reports a symptom without repairing the decision. |
| Spec repair assistant | ESCALATED | Stronger than detection, but still single-shot. |
| Decision compiler | KEEP | Human clarification becomes spec patch + code repair + regression contract + decision memory. |
| Semantic CI guard | KEEP | Resolved decisions constrain future agent work and can block semantic regression. |
| Specification fuzzing | KEEP AS CATEGORY MECHANISM | Parallel independent interpretations become probes for under-specified boundaries. |
| Fresh-agent replay | NORTH STAR / PENDING_LIVE_BOB | Strong second-order proof, but must not be simulated or claimed without a genuinely fresh agent run. |
| Generic agent orchestrator | REJECT | Dilutes the specific failure class and category. |
| Dashboard / analytics expansion | REJECT | Adds surface area without strengthening the central mechanism. |
| LLM confidence scoring | REJECT | Adds probabilistic noise at the truth boundary; consensus/confidence is not evidence. |

### Depth checks

- **Mechanism depth:** PASS — disagreement is converted into a classified truth problem, not just visualized.
- **Causal depth:** PASS — the system distinguishes explicit-source agent drift from source-silent specification gaps.
- **Agency:** PASS — a human decision is compiled into executable consequences.
- **Second-order consequence:** PASS — decision memory changes future behavior through the guard.
- **Abstention depth:** PASS — UNKNOWN is preserved when authority is absent.
- **Category strength:** PASS — Semantic CI / specification fuzzing is stronger than “repair assistant”.
- **North Star preserved:** PASS — replay and earlier-stage spec fuzzing remain future extensions without shrinking the current wedge.
- **Feature-bloat guard:** PASS — rejected expansions do not strengthen the thesis.

### Creative Depth verdict

**PASS**

The concept is allowed to proceed as **Semantic CI for Agentic Software Development**. The current demo wedge remains intentionally narrow, but the product vision is not reduced to the wedge.

## Gate B — Distinctiveness Escalation

### Functional baseline

The working product already proves:

- `DECISION_REQUIRED` from a true `SPEC_GAP`.
- `KEEP UNKNOWN` as a correct abstention path with no canon or repair.
- Interactive `USE account_id` decision.
- Decision compilation into spec patch, targeted code repair, executable regression contract, and decision memory.
- Integration conflicts reduced from `2 → 0`.
- `SEMANTICALLY_READY` after verification.
- Future incompatible agent change triggers `MERGE_BLOCKED`.
- Exact restoration returns the workspace to verified `SEMANTICALLY_READY`.

### Escalation challenges

| Challenge | Result |
|---|---|
| Read-only bias | PASS — COLLIDER mutates an isolated workspace and compiles the decision. |
| Single-shot demo bias | PASS — guard provides a real second act. |
| Memory without consequence | PASS — persisted decision memory constrains future work. |
| Happy-path bias | PASS — KEEP UNKNOWN and MERGE_BLOCKED are visible counter-cases. |
| Feature-as-product bias | PASS — category is Semantic CI, not a collection of UI features. |
| Implementation-shaped vision | PASS — North Star is specification fuzzing + executable decision memory, not the current fixture. |
| Weak demo surface | PASS — the judge can provoke the decision, compile, guard, block, and restore. |
| Sponsor-native weakness | PARTIAL — Bob was load-bearing in implementation and architecture; live parallel Bob generation remains unproven because the canonical interpretations are PRESEEDED. |
| No signature moment | PASS — `MERGE BLOCKED` after a future agent violates resolved canon. |
| No before→after proof | PASS — `2 conflicts → 0`, then future regression blocked. |
| Architecture-as-pitch bias | PASS — judge-memory sentence is product behavior, not architecture. |
| Feature-bloat risk | PASS — no new feature is required for Demo Lock merely to appear “more ambitious”. |

### “Can this go further?” pass

The answer is **yes at the North Star level**, but not every deeper idea belongs in the submission build.

The strongest next conceptual extensions are:

1. **Fresh-agent replay** — a genuinely new independent agent reinterprets the repaired spec; if divergence disappears, the repair is proven to generalize.
2. **Pre-implementation specification fuzzing** — deliberately generate independent interpretations before code is written to discover missing decisions earlier.
3. **Semantic lockfile / decision contract** — make resolved decisions portable across future agent sessions and repositories.

For the current hackathon build:

- (1) remains **PENDING_LIVE_BOB** and must not be simulated.
- (2) is a **North Star expansion**, not required to prove the current wedge.
- (3) is already materially represented by decision memory + regression contract + guard, so adding another surface would mostly rename existing behavior.

### Distinctiveness verdict

**PASS FOR CURRENT BUILD**

No additional feature is required before Demo Lock. The required escalation is conceptual and narrative: present COLLIDER as **Semantic CI / specification fuzzing**, with the executable decision loop and guard as the proof.

This verdict does **not** declare the product finished forever. It means the current vertical slice is sufficiently active, deep, distinctive, and demonstrable to move into final validation gates without adding feature bloat.

The build may move forward only with these truths preserved:

- PRESEEDED interpretations are never narrated as LIVE_BOB.
- Fresh-agent replay remains `NOT_EXECUTED / PENDING_LIVE_BOB`.
- Consensus does not become truth.
- UNKNOWN remains first-class.
- Public runtime proof, session isolation, mobile smoke, Judge Performance Assurance, Pre-Launch / Ship Assurance, Submission Integrity, and Final Snapshot remain separate gates.
